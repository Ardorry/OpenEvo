3. 为什么 Train 提升没有转化为 Test

Train Round 0 为 382/450（84.89%），同题监督后的 Round 1 为 402/450（89.33%），+4.44 pp，p=0.001658。Round 1 已接收当前题 GT，因此衡量即时纠错，不是独立泛化。Temperature 在 Train 从 76% 到 96%，盲测却从 generation-zero 94% 到 evolved 82%，是最强的过拟合/负迁移信号。

4. 机制审查

  1. 无 held-out promotion：最终 27 个 artifact 全部 promoted，但 scores 全空；格式验证不等于效果验证。
  2. latest-head 偏置：每类单题滚动更新 50 次，固定冻结 task 49/cycle 1，没有 champion 比较或回滚。
  3. 递归摘要偏置：每次 dataset 只含当前 supervised packet 分片，历史靠 predecessor artifact 递归保存，容易 recency drift 与遗忘。
  4. 三目标放大：同一监督信号同时改 memory、skill、agent-system，缺少职责隔离、冲突检测和 target ablation。
  5. 上下文负担：Temperature 最终 payload 最大，约 17.1 KiB；这是需要验证的 prompt overload 假设，不是已证因果。
  6. 高 baseline ceiling：多个类别已达 98%–100%，不稳健上下文更容易造成回归。

5. 推荐改进

  1. Champion/candidate gate：把 Train update 与冻结 validation 严格隔离；candidate 只有在 paired validation 胜过 prior/generation-zero 后才晋升，否则回滚。
  2. 批量而非逐题更新：每 10–25 题汇总一次跨题证据，保留 support/contradiction/适用条件；不要让最后一题主导最终状态。
  3. 先做 memory-only：再依次做 skill-only、agent-only、组合 ablation。Agent-system 只保留不变纪律，skill 只保留流程，memory 承载类别知识。
  4. Canonical rule IR：从同一证据表投影三个 target，跨 target 去重和冲突检查；总上下文先压到约 4–6 KiB，再由 validation 决定是否扩张。
  5. Temperature 专项：仅用 Train 内未曝光 fold 比较 generation-zero、memory-only、full-three；无法稳定胜出就明确选择 generation-zero。
  6. 重复实验：dev/validation 每 arm 至少 3–5 个 replicate，报告 paired CI、negative flips 与分层 bootstrap，避免用一次 one-shot 差值判定。
  7. 保护盲测：当前 Test aggregate 已用于诊断，后续不读取逐题内容、不据逐题错误调规则；确认性结果使用新的 never-exposed holdout。

6. 下一轮最小实验

先不重跑现有 Test。Stage A 只在 Temperature + Yield 的 Train/validation 上比较 generation-zero、memory-only、full-three，每 arm 至少 3 个 replicate；Stage B 再扩到九类，并允许每类独立选择 generation-zero。成功标准改为可重复的 held-out paired gain，而不是 Train R1 高于 R0。

7. 审计边界

两组均为可审计的 parent-prefix + recovery-suffix 组合，不是一次未中断运行；同 UID、顺序、split/config/model/runtime identity 均已绑定，公开 compatibility receipts 通过。每题仅一个有效 completion，故本报告是 paired descriptive comparison，不是随机化重复因果试验。
