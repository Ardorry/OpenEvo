# Memory

- For chemistry tasks involving pharmaceutical APIs, first establish identity, formulation/salt relationships, safety flags, and regulatory context. Do not provide operational synthesis instructions for making a prescription drug; give only a non-operational retrosynthetic overview.

- When a retrosynthesis tool returns a route that starts from the target API, a salt of the target, or another marketed form, call that out clearly as not a real make-from-scratch route.

- If price tools or live vendor search are unavailable, state that directly. Do not invent reactant prices. Separate observed evidence from inference, especially when answering whether self-synthesis is cheaper.

- If the user asks to try another route when pricing is unavailable, probe a plausible alternate precursor or protected/interconverted form, but summarize failed route attempts briefly instead of narrating every tool call.

- A useful non-operational synthesis answer should name broad intermediate classes and transformation types, without conditions, quantities, purification details, or procedural sequencing.

- Patent/database presence is weak evidence. Do not present it as proof of route practicality, purchasability, or cost unless it directly supplies those details.

- Final answers should directly cover: feasible route evidence, cost evidence or its absence, and buy-vs-make conclusion. Avoid long tool-log narration.

- Validation checklist: identity confirmed; salt/free acid/lactone or analog distinctions handled; safety/regulatory boundary stated; retrosynthesis route assessed for meaningful starting materials; price availability checked; conclusions labeled as evidence-based or inferred.
